# CopyLoop MVP 验收契约

版本：0.1-draft · 状态：目标已定义，所有运行结果为 not_run。

下列数值是第一版工程验收目标，不是已测性能或行业通用标准。在 M1 先验证参考自身可重复性，冻结合同与 hash；后续不得为通过某个候选而暗改阈值。

## 1. 判定规则

单项状态：`pass`、`fail`、`unknown`、`not_run`、`out_of_scope`。必需门槛全部 pass 才能发布 case-001 alpha。未知、缺失、跳过和范围外不能折算为通过；不使用加权总分覆盖失败。

所有发布验收使用同一 candidate revision、case hash、seed hash、environment lock 和断言版本。每个流程在两个视口各连续成功三次；发生失败保留失败记录，修改后重新验收。环境中断另记 unknown，不计为成功；同样不能声称这是一组不中断通过的结果。

## 2. 必需门槛

| Gate | 必须满足 | 证据 |
| --- | --- | --- |
| G0 参考可靠 | 固定 commit 与镜像；参考全流程可运行；每个视觉状态三次自比较稳定 | 环境锁、seed/reset 收据、参考轨迹 |
| G1 功能 | J01–J10 × 2 视口 × 3 次，60/60 成功 | 每步接收端断言、完整结果集合、持久化校验 |
| G2 未知输入 | H01–H04 × 2 视口 × 3 次，24/24 成功 | 冻结后生成的输入、seed 承诺 hash、前后数据 |
| G3 视觉 | 12 个检查点全部达到下述像素与布局标准，每轮分别通过 | 原图、差异图、元素框、文案断言 |
| G4 动效 | 3 个观察对象 × 2 视口 × 3 次；支持范围内全部通过；即时状态同样验证 | 原始时间戳、属性采样、关键帧、校准结果 |
| G5 独立运行 | 参考服务停止后再跑 J01–J10，两视口各一次，20/20 成功 | 网络记录、参考停机证明、候选存储与结果 |
| G6 工具有效 | 能拒绝规定的错误候选和坏证据；缺失不能返回成功 | 正负校准、报告/退出码一致性测试 |
| G7 可交付 | 干净环境安装构建启动成功；完整源码/锁文件/许可证/报告；另一位开发者可复跑 | 操作记录、构建 hash、二次复跑记录 |

G7 的独立开发者复跑未发生时可交付 internal candidate，不能标记公开 alpha 验收完成。无需为本次文档与仓库创建安排该复跑。

## 3. 视觉标准

固定 Chromium、OS/容器、字体、DPR、主题、滚动位置、时间和数据。等待字体加载、图片解码及指定状态稳定后截图。不得用整页蒙层、截图贴图或 DOM 替换绕过页面实现。

- 比较算法锁定为 pixelmatch，`threshold=0.1`、`includeAA=false`；首轮实现固定依赖版本。
- 每张全视口图 changed-pixel ratio ≤ 1%；列表、搜索框、表单和主按钮的预登记区域各 ≤ 2%。
- 主要元素边界差异 ≤ 4 CSS px；同一视口的主要文字换行数一致，无遮挡或水平溢出。
- 用户内容、可见状态、标签、计数与可访问名称必须语义一致；像素达标不能覆盖缺字、空结果或错误数据。
- 参考对自身的三次截图差异必须 ≤ 0.2%；超出先修参考稳定性，不能直接放宽候选阈值。
- 允许 mask 仅限冻结前登记的品牌标识与确实不可固定的区域，合计面积 ≤ 1%；每个 mask 在报告显示坐标、理由和原始未遮罩图。不得 mask 任何主操作或测试数据。

如果字体/渲染导致同一环境也无法满足阈值，标为 environment-unstable 并暂停视觉判定。任何阈值修订需要新版合同和新运行，保留旧结果。

## 4. 动效标准

运动采集不得设置 `animations: disabled`。静态比较可以在动画结束后截图，但不能拿它当动效证据。

对能观测的动画同时保存真实时间轴与采样质量：目标 60 Hz；记录实际间隔，采样间隔 p95 > 25 ms 或存在 > 50 ms 缺口时该次结果为 unknown。没有动画时保存触发前后状态及短时间窗口，证明不存在额外运动。

- 持续时长误差 ≤ max(33 ms, 参考时长的 10%)。
- 平移/尺寸轨迹按实际时间和进度分别比较，坐标误差 ≤ 4 CSS px；opacity 绝对误差 ≤ 0.05。
- 初始/最终状态必须正确；方向、触发条件、退出方式及重复触发结果必须一致。
- 原站即时切换时，候选不得引入持续 > 33 ms 的额外过渡。
- 重复触发或中途取消若不在声明的支持范围，明确 unknown，不能把两端截图相同当通过。

工具校准：使用自有固定 200 ms 的 transform/opacity 样本。正确实现必须通过；400 ms 错误时长、完全禁用动画、错误终点必须失败；人为缺帧必须 unknown。这只验证仪器，不证明复杂 JS/Canvas 动效能力。

## 5. 接收端和数据标准

点击成功、请求 200、构建成功、脚本跑完均不是用户流程成功。必须检查动作后的独立可见状态，并在持久化场景重新读取。

J10 关闭浏览器时保留当前测试 profile，重启服务后重新打开，读取真实 IndexedDB；清空 profile 的首次启动与持久 profile 的重开不能混用。参考持久化也通过自身重启验证。页面内存、导出 JSON 快照或测试脚本临时缓存不能替代底层持久数据。

主路径每步等待上限 5 秒，超时 fail 并保存最后状态。稳定的本地文字交互 p95 ≤ 200 ms（输入事件到包含正确结果的下一次绘制），导航、安装和冷启动另计；原站相同配置下的数值同时展示，不将任意长 sleep 解释为性能通过。

## 6. 负向校准与独立性

G6 至少拒绝：按钮无效果、数据只存在内存、漏掉中文字符、错误标签过滤、重复保存新增两条、整页截图伪装、原站 iframe/API 代理、陈旧 candidate hash、缺失截图/轨迹，以及把 unknown 汇总为 pass 的报告。

验收器与预期结果不能由生成候选的 agent 修改。固定测试行为不依赖候选专属后门；允许正常 UI role/label 适配，映射只定位元素，不能改预期集合或直接写数据库完成用户操作。重置/seed 是每条测试前独立执行的环境步骤。

自动修正最多 3 轮。任何人工改候选代码、提示词或测试适配都记录，区分 autonomous 与 assisted 结果。展示全部尝试而非仅最佳一次。

## 7. 报告最小字段

`case_id`、`run_id`、`spec_sha256`、`seed_sha256`、`reference_revision`、`reference_runtime_digest`、`candidate_revision`、`environment`、`generator_access_mode`、`attempts`、`human_interventions`、`journeys`、`visual`、`motion`、`independence`、`delivery`、`cost`、`limitations`、`overall_status`。

每项结果引用本次 run 的 artifact 路径与 hash。报告可离线查看，能打开实际截图与差异；默认不上传 browser profile、登录信息或用户内容。公开示例只包含可分发的合成数据。
