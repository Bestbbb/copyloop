## 2. 本案例交付

一个独立、可构建的本地书签网站，复现下面的十条核心流程以及选定页面状态。候选使用独立 IndexedDB 存储；参考使用自身数据库。允许内部实现不同，但用户可见语义、持久化和流程结果必须一致。

视觉模式只评估上游英文 UI、浅色主题；中文与 emoji 作为用户数据验证。复制 UI 文案和实际行为，不复制上游商标图形。候选页眉使用同布局的 CopyLoop Case 标识，该区域列为预先声明的品牌差异。候选不能通过加载原站实现功能。

范围外：登录/账号系统、分享、团队权限、全文网页归档、元数据联网抓取、导入导出、浏览器扩展、复杂布尔检索、批量操作、设置中心和深色主题。

参考 UI 如果展示范围外控件，冻结时选择隐藏配置或将相应区域明确列入范围外；不能留看似可用但实际无效的候选按钮。基准需展示所有排除项，不将裁剪后的结果描述为全站复刻。

## 3. 固定环境与数据

视口：1440×900 和 390×844，DPR=1，语言 en-US，时区 UTC，浅色主题，reduced-motion=no-preference。两者都由同一锁定 Chromium 执行，第二种只是移动尺寸视口。

使用 [seed.json](../cases/linkding-v1/seed.json) 中 12 条合成书签、固定时间和固定排序。每条 journey 独立 reset，避免前一条的新增影响后一条的计数。参考与候选都从各自存储加载相同 seed。

种子 URL 使用 `.test` 域名。M1 提供离线 fixture 页面并通过受控 resolver/路由映射到本地服务；书签导航必须真正打开对应测试页面并验证页面标记。元数据抓取关闭或定向到同一合成 fixture，不能依赖外部网站实时标题、图标或网络。

静态基线固定时间显示；真实响应与动效测试保持真实时钟，不用冻结时钟掩盖异步或时长问题。cookie 提示、自动更新、随机内容和外部字体必须在观察冻结前处理并记录。

## 4. 核心流程

| ID | 操作 | 接收端必须证明的结果 |
| --- | --- | --- |
| J01 | 打开列表，打开一条书签 | 全部 seed 可访问、排序匹配；新页面出现该 URL 对应的 fixture 标记 |
| J02 | 新增 URL、标题、描述与两个标签并保存 | 数量从 12 到 13；文字逐字符匹配；刷新后仍可检索 |
| J03 | 搜索 `CSS`，清空，再搜索不存在的词 | 返回与参考相同集合；清空恢复列表；无结果状态真实出现 |
| J04 | 选择 `#research` 标签，清除筛选 | 只展示匹配集合；清除后恢复全部；URL/控件状态与操作一致 |
| J05 | 编辑现有标题、描述和标签 | 数量仍为 12；新值可检索，旧值不残留；刷新后保持 |
| J06 | 再次添加已存在的完整 URL | 按参考的重复 URL 更新语义处理；不得新增第二条；再次读取内容一致 |
| J07 | 修改表单后点 Cancel | 关闭/返回行为匹配；任何字段和记录数量均未发生持久修改 |
| J08 | 删除现有记录，覆盖参考存在的取消路径 | 成功删除后数量 11，刷新/搜索仍不存在；有取消路径时取消不删数据 |
| J09 | 用 Tab、Shift-Tab、Enter 完成新增并继续输入 | 标签可访问、焦点可见、顺序合理；一次保存一条记录，没有误提交 |
| J10 | 新增、编辑后重启候选服务并关闭/重开浏览器 | 使用同一持久 profile 后数据、标签与数量精确匹配；不能只验证页面内存 |

J06 的重复处理依据上游表单中的说明；仍须在 M1 通过参考 UI 实测。J08 不预设参考有确认弹窗。其他未观察细节先记 unknown，M1 冻结后成为可执行断言。

## 5. 独立 holdout

验收器另生成以下四类数据，各在两个视口运行三次。具体值和随机种子在候选冻结前不交给生成器；运行后随报告公开。不能将公开固定样例称为未知测试。

| ID | 类别 | 断言 |
| --- | --- | --- |
| H01 | 中文、emoji、标点和长标题 | 保存、编辑、搜索、重新读取不丢字符，布局不遮挡主操作 |
| H02 | 空 URL 或明确非法 URL | UI 明确反馈，记录数不变，焦点仍能继续编辑 |
| H03 | 新的重复 URL 与标签组合 | 满足与参考一致的更新、筛选和数量不变量 |
| H04 | 连续保存/双击保存与随后刷新 | 不产生额外重复记录、不丢最后确认内容；参考存在歧义时先归类再冻结合同 |

允许生成器知道测试类别和产品语义，不向它提供 holdout 实际值及接收端结果。修正若使用了某批 holdout 结果，该批转为开发用例，发布验收必须重新生成一批。

## 6. 视觉与动效检查点

六个视觉状态 × 两个视口：初始列表、搜索结果、无结果、标签筛选、新增表单、编辑表单。每个状态保存参考图、候选图、差异图、DOM/AX 和主要元素边界。删除及错误反馈另外作为功能证据，不扩大首批视觉状态数量。

三个动效观察对象：标签建议开/关、Notes 展开/收起、表单焦点与校验反馈切换。M1 先确认这些控件在固定设置下实际出现，并记录是否即时切换。原站没有连续动画时验收“没有额外动画”；无法观察的对象为 unknown，必须修订对象选择后重新冻结，不能直接计 pass。

动效校准样本是工具自身测试，不算第二个产品复现案例。它验证已知动画与故意错误动画能否被区分；详情见验收契约。

## 7. 防止伪复现

生成器只能访问冻结的观察证据和批准资源。参考运行代码、数据接口凭据、实现源码和评测器不进入候选工作区。评测器独立校验显示文本、结果集合、实际存储和独立页面，不只看 click/fill 是否返回成功。

最终断开参考服务，在已有依赖和本地构建下重跑核心流程；拒绝 iframe、参考 API 代理、静态截图覆盖或写死 seed 结果。候选自身必须处理新的输入。
